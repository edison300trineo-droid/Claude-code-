# qpcr-biod — Alu qPCR 生物分布數據統整 pipeline

把原本只能在單一 Cowork 對話裡重現的 qPCR 統整流程，變成一個任何人都能重跑的專案。

## 為什麼要做成專案

原本的做法是：把原始檔給助理，助理讀檔、套規則、產出統整表。問題不在統整表本身，
而在**規則只存在於對話裡**——所以只有發起那個對話的人能更新，同仁沒辦法接手，
也沒辦法驗證某個數字是怎麼來的。

這個專案把規則從對話搬進程式碼與設定檔，於是：

* 任何人只要有這個資料夾就能產生一模一樣的統整表
* 每個數字都能追回原始檔的哪一孔
* 人工判斷（誰、什麼時候、為什麼）跟著資料一起留存

## 三條設計原則

1. **原始檔是唯一真實來源，pipeline 只讀不寫。**
   StepOnePlus export 永遠不會被修改。測試裡有一條專門檢查這件事。
2. **統整表是產出物，不手改。**
   每次重跑整份覆蓋。手改的東西下次就會消失——所以不要手改。
3. **人工判斷寫在 `decisions.xlsx`。**
   每筆決策都要填覆核者與日期，缺一就不生效並在執行時提示，不會靜默套用。
   決策內容會寫進產出檔的「執行紀錄-人工決策」分頁。

## 資料夾結構

```
qpcr-biod/
├─ config/
│  └─ BD-TS-20260701.yaml     ← 規則都在這裡（允收標準、LOB、臟器代碼…）
├─ data/
│  ├─ raw/                    ← 原始 StepOnePlus export (.xls)，只放不改
│  ├─ reference/              ← 動物分組/性別/上機編號等參考檔
│  └─ decisions.xlsx          ← 人工決策表（唯一可編輯的檔案）
├─ output/
│  └─ BD-TS-20260701_統整表.xlsx   ← 產出，每次重跑覆蓋
├─ src/qpcr_biod/             ← 程式
├─ tools/                    ← 安裝與對帳的輔助腳本（.bat 呼叫它們）
└─ tests/
```

`config/*.yaml` 的 `paths` 區塊可以直接填 NAS 路徑（含 UNC 路徑），
相對路徑則以設定檔所在資料夾為基準。

## 安裝

```bash
pip install -e ".[dev]"
```

需要 Python 3.10 以上。

## 使用

```bash
# 產生空白決策表（已存在時不會覆蓋）
qpcr-biod init-decisions -c config/BD-TS-20260701.yaml

# 產生統整表
qpcr-biod run -c config/BD-TS-20260701.yaml
```

Windows 上可直接雙擊 `執行統整.bat`。

> 三個 `.bat` 刻意保持**純 ASCII**。cmd.exe 在 `chcp` 之後會用切換前的編碼
> 計算檔案位置繼續讀取，含中文的批次檔會被從中間切碎，碎片被當成指令執行
> （典型症狀：`'----------' 不是內部或外部命令`）。所有中文訊息都由
> `tools/` 底下的 Python 腳本輸出，`.bat` 只負責找到 Python 並轉呼叫。

新增資料時的流程就是：把新的 .xls 丟進 `data/raw/`，重跑一次。
已處理過的檔案不需要特別標記——pipeline 每次都從全部原始檔重新計算，
所以不會有「漏匯入」或「重複匯入」的狀態問題。

## 產出的分頁

| 分頁 | 內容 |
|---|---|
| 說明 | 本次執行的規則摘要與注意事項 |
| 統整數據 | 每列 = 動物編號＋臟器代碼＋來源檔案；含兩孔明細、LLOQ、ND 判定 |
| Organ Mean SD Summary | 依臟器、性別、時間點的 Mean±SD 報告表 |
| 血液LOB校正 | LOB 計算依據、逐檢體比對、校正後彙整 |
| 標準曲線與QC ／ QC點位明細 | 每個 run 的回歸統計、允收判定、QC 點位 |
| 臟器代碼對照表 ／ 動物分組與性別對照表 | 對照資料與其來源 |
| 批次與上機編號進度表 | 批次組成，以及每個 Run 對應的批次／時間點／原始檔 |

### 資料來源優先序

臟器代碼、批次組成與 Run 排程的來源優先序是：

**人工決策表 > 官方「上機編號_說明」對照表 > 設定檔**

設定檔裡的對應內容只是官方檔缺席時的備援，產出表會註明每一筆的實際來源。
| Raw_Import | 所有原始檔的完整逐孔資料 |
| 執行紀錄（4 頁） | 輸入檔 SHA-256、套用的人工決策、所有警告 |

統整數據的底色：淺紅＝請人工複核；淺綠＝ND 屬預期現象；淺灰＝非最終採用（保留供追溯）。

## 已知的儀器怪癖（都已處理）

* **Ct 欄名不是拉丁字母**。StepOnePlus 匯出的表頭寫成 `Cт`、`Cт Mean`、`Cт SD`，
  那個 `т` 是西里爾字母 U+0442。逐一猜變體會漏，所以比對欄名前先做同形字正規化
* **`.xls` 是真的 BIFF 檔**，不是偽裝成 .xls 的分隔文字（但兩種都支援）
* **HIGHSD 欄位可能整欄不存在**。儀器只在整盤有 HIGHSD=Y 時才輸出該欄，
  整盤皆為 N 時本來就沒有這一欄，屬正常現象
* **Run 結束時間同時有 24 小時制與 AM/PM**（`2026-08-25 18:44:30 PM CST`），
  也可能是 `Not Started`
* **濃度以 float32 儲存**，3.2 會寫成 3.200000048，所以標稱濃度比對用相對容差

## 內建的判定規則

規則都寫在設定檔裡，改設定檔即可，不需要改程式。

* **標準曲線**：Ct vs log10(Quantity) 線性回歸；允收 R² ≥ 0.98、PCR 效率 85–115%
* **標準曲線回歸基準**：每個標準點取 Ct 平均後回歸（n = 標準點數），
  與既有統整表的 n=8 一致。平衡設計下逐孔回歸的斜率／截距相同，
  但 R² 會把孔間變異算進殘差而偏低——R² 是允收標準，所以這個選擇會影響判定。
  設定檔 `fit_basis` 可切換為 `well`
* **標準品序列**：STD01 起一路 5 倍序列稀釋至 STD08
  （10000 / 2000 / 400 / 80 / 16 / 3.2 / 0.64 / 0.128 pg）。
  回歸取儀器實際輸出的 Quantity，不取設定檔數值；但每個 run 都會比對兩者，
  設定檔序列填錯時會警告
* **LLOQ**：取該 run 標準曲線最後一點（STD08）的實際濃度，逐 run 各自認定
* **ND**：Quantity Mean 低於該 run LLOQ 標示 ND；原始測得值另存一欄不覆蓋
* **Rerun**：兩種機制並存，且可能出現在同一塊盤上——
  名稱後綴（`1011_03` 與 `1011_03_re`）與「同一動物＋臟器出現在較晚的 run」。
  因此版本的身分是 **(來源檔案, Sample Name)**，不是只看來源檔案。
  最終採用取最新的複測：排序鍵為 (run 順序, 是否為名稱標記的 rerun)，
  所以同盤的 `_re` 勝過同盤的原始，較晚的 run 又勝過同盤的 `_re`。
  非最終版本一律保留供追溯
* **HIGHSD**：最終採用列仍為 HIGHSD=Y 且無 rerun 時，系統**不自行選孔**
  （匯出檔未附擴增曲線，無法客觀判斷）。可定量者標「請人工複核」，
  ND 者標「屬預期現象」——低濃度時孔間微小差異本來就容易觸發 HIGHSD
* **回收率**：以敏感度對照組為唯一判定依據（80–120%）
* **NTC**：Alu 為高敏感度方法，微量背景屬正常；僅在回推濃度 ≥ 該 run LLOQ 時才判異常
* **血液 LOB**：由 Predose 血液孔位層級資料建立（Mean + 1.645×SD）；
  陽性需同時「非 ND」且「≥ LOB」；Predose 為 LOB 定義組，欄位標示為 `-` 不予計算
* **組別**：依採樣時間點判定；同一時間點對應多組時標為「待確認」，
  等決策表指定，不猜測
* **性別／時間點**：只從參考檔取得，不由動物編號前綴推測；
  多個參考檔不一致時留白並提示，不擅自選一個。
  官方「上機編號_說明」對照表由專門的解析器處理——那份檔案是自由格式，
  性別靠「動物編號寫在 M 欄還是 F 欄」表示，不是一個欄位值
* **時間點寫法**：官方表寫 `Pre-dose` / `Day 02` / `1 hour`，
  統整表用 `Predose` / `Day 2` / `1h`；載入時收斂成同一種，
  否則同一個時間點會被當成兩個而把 Mean/SD 拆散
* **批次與 Run**：同批次的臟器在同一個 Run 內一起上機。官方對照表只排定了
  前 6 個 Run，其餘由實際資料逆推；兩者在報表中分別標示為
  「官方上機編號對照表」與「依實際匯入資料逆推」，不會混為一談。
  Run 編號本身也是推定值（原始檔內沒有這個欄位），表上會註明

## 這個 pipeline 刻意不做的事

有些判斷不該由程式代勞，硬做只會把不確定性藏起來：

* 不會在 HIGHSD 時自行選孔
* 不會把 ND 用 LLOQ/2 之類的值代入 Mean/SD 統計（只有繪圖用資料才代入，且另立欄位）
* 不會在時間點無法唯一對應組別時猜組別
* 不會在參考檔互相矛盾時挑一個用
* 不會修改或刪除任何原始資料

以上情況一律留白或標記，並寫進執行摘要與「執行紀錄-警告」分頁。

## 測試

```bash
pytest
```

測試涵蓋 parser（含真 .xls 與偽裝成 .xls 的分隔文字）、分類、標準曲線允收、
QC 判定、ND／HIGHSD／rerun 規則、LOB 陽性判定、決策表往返，
以及「原始檔不被改動」與「重跑結果一致」兩條不變式。
